## 年视角还是 0 数据 → 时区 bug 连锁
- 用户反馈改完之后年视角还是没数据 → 深入排查发现**两个 bug 叠加**：
  1. 之前发现的 `sessionMap.get('YYYY-MM')` 永远拿不到（`readingSession.date` 是 `YYYY-MM-DD`）。
  2. `case 'year'` 用 `new Date(year, month, 1).toISOString().slice(0,7)` 生成 key，在 UTC+8 时区下会**整体偏移一个月**：`dateKeys[0] = '2025-12'`（本应是 `2026-01`），`dateKeys[7] = '2026-07'`（本应是 `2026-08`）。即便 1️⃣ 修了，2️⃣ 还会让今天 `2026-08-12` 命中到标签「9月」。
- 改动（service.ts `case 'year'`）：dateKeys 直接用 `d.getFullYear() + '-' + padStart(month, 2, '0')`，绕开 `toISOString` 的时区换算。
- 顺带发现：`case 'week'` / `case 'month'` 也有同样的 toISOString 时区问题（key 偏一天），但因为月/周范围大，多数 session 还能命中，所以「看起来有数据」。本次只修年视角，等用户确认后再决定是否要统一处理（涉及数据语义，要跟用户讨论「今日」到底是按 UTC 还是按本地时区算）。
- 验证：本机 node 模拟 Asia/Shanghai 时区跑过：年视角 `2026-08` key 能正确命中 `2026-08-12` 这条 session。`tsc --noEmit` 通过。

## 创建订单失败的真正根因：VipCurrentLowestPriceData 字段不匹配

- 用户反馈："创建订单失败"。我第一轮判断成了"401 token 缺失"，修了 App.tsx 启动重水合 token。但用户纠正："接口是有的，是没用当前最低价格，用的是默认兜底"。
- 真正根因：
  - `apps/mobile/src/services/plus.ts` 我前一版补的 `VipCurrentLowestPriceData` 是 **平铺 number**：
    `annual / lifetime / annualPrice / lifetimePrice` 全是 number。
  - 实际 AudioDock shared Plus 后端 `/vip/current-lowest-price` 返回的是 **嵌套对象**：

  - plus.ts 改 `VipCurrentLowestPriceData` 为 AudioDock 形状：`annual / lifetime: VipCurrentLowestPricePlan | null`，新增 `VipCurrentLowestPricePlan { originalPrice, discountPercent, currentPrice }`，对齐 `AudioDock/packages/services/src/plus.ts:189`。

## 致命教训：plusRequest interceptor `return data` 后不能再 `.data`

- 用户反馈"价格还是 20/60，但你说请求是对的"。我加了页面 DEBUG 面板直接渲染 `JSON.stringify(priceRes)`。
- 截图里 JSON 直接暴露问题：输出的 JSON 没有 `code` / `message` 字段，只有 inner data 的 6 个键。
  也就是 `priceRes` 不是 envelope `{code: 200, message: "success", data: {...}}`，而是 envelope 的内层 data。
- 根因：plus.ts 那 6 个补回的支付函数，全错成 `res.data as ISuccessResponse<T>`。
- 机制：
  - plusRequest.interceptors.response.use 已经 `return data`（即 response.data），所以 `await plusRequest.get(...)` 拿到的已经是 envelope。
  - 我的 plus.ts 函数又取了一次 `.data` —— 实际是 envelope 的 `.data` 字段，把内层当成 envelope 返回。
  - 调用方 `priceRes.code === 200` 永远是 `undefined === 200 = false`，`setPricing` 那行从来没进过，UI 一直 fallback 到 STATIC_PRODUCTS.fallbackPrice（20/60）。
- 修复：6 个函数全改成 `return res as unknown as ISuccessResponse<T>`（二段 cast 因为 axios 静态类型 AxiosResponse 与 ISuccessResponse 形状不重叠，TS 拒绝直接 as）。
- 教训（重要，写进 MEMORY.md）：
  1. 下次接手 apps/mobile/src/services/plus.ts 的请求函数，记住 plusRequest 是已经被 interceptor unwrap 的 axios instance。res 已经是 envelope，不要再加 .data。
  2. AudioDock 那边的 plusGetVipCurrentLowestPrice 是 `return plusRequest.get(...)` 不 unwrap —— 这才是正确范式。我之前手贱加 unwrap 是错的。
  3. 排查 silent fallback 时，直接 render 原始响应 JSON 到页面比改来改去更快定位 —— 这次用户让我加 debug panel，看 1 张截图就定位到了。
