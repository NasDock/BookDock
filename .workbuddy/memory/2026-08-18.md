## ArkTS 严格模式编译错误修复（2026-08-18 16:11 第二轮编译反馈）
- DevEco Studio 编译报 **218 ERROR + 36 WARN**，集中在以下规则：
  1. `arkts-no-any-unknown`：禁止 `any` / `unknown` 关键字（注释除外）
  2. `arkts-no-indexed-signatures`：interface 内禁止 `[key: string]: V`
  3. `arkts-no-props-by-index`：类字段禁止 `obj[key]` 索引访问
  4. `arkts-no-untyped-obj-literals`：对象字面量必须对应显式 class/interface
  5. `arkts-no-obj-literals-as-types`：对象字面量不能作为类型声明
  6. `arkts-no-spread`：`{ ...a, ...b }` 仅数组允许
  7. `arkts-no-destruct-params`：形参禁止解构 `{ a, b }: { a, b }`
  8. `arkts-no-structural-typing`：禁止结构化类型
  9. `arkts-no-inferred-generic-params`：泛型调用必须显式指定类型参数
  10. `arkts-limited-throw`：`throw` 只能接 `Error` 实例，不能 throw 任意类型
  11. `arkts-no-misplaced-imports`：`import` 必须全部在文件顶部

- **修复模式**（已沉淀到所有 P0+P1 文件）：
  - `Record<string, X>` → `ESObject`（ArkTS 标准 escape hatch，允许任意键访问）
  - 类实例字段索引访问 → 先把字段 cast 成 `ESObject` 再 `['key']` 访问
  - `Request.method`/options 等 RN 内置解构 → 显式命名参数
  - `{ ...payload, foo: bar }` spread → 手动赋值 `const payload: ESObject = {}; payload['foo'] = bar;`
  - 对象字面量作为形参类型 → 改用具名 interface 字段（如 `StringMap = ESObject`）
  - `throw err` → `throw new Error(String(err))` 或具名 `Plus HTTP ${code}`
  - `Indexed signatures are not supported (arkts-no-indexed-signatures)` → 用 `ESObject` 而不是 interface 内的 `[key: string]`

- **额外踩坑**（DevEco 7 / API 12+ 鸿蒙 SDK 实际行为）：
  1. `SymbolGlyph('diamond')` 字面量在 strict 模式下需要 `SymbolGlyph($r('sys.symbol.diamond'))` 形式 —— SymbolGlyph 的 `value` 必须是 `Resource`，不能是字符串
  2. `SymbolGlyphAttribute` 没有 `textAlign` 属性，要包一个 `Row { }` 给 SymbolGlyph 提供对齐上下文
  3. `@kit.ArkUI` 不导出 `Tabs/TabContent/TabBar/TabBarItem` —— 这些是 ArkUI 全局组件，直接用即可，不需要 import
  4. `mediaquery.Orientation` 类型在 ArkTS 中不可用（namespace 无此导出），只能用作枚举值字符串 'landscape' / 'portrait' 自行比较
  5. `ApiResponse` / `User` 应从 `../model/ApiModels` 导入，不要从 `../network/ApiClient`（ApiClient 只 re-export 自己的类）
  6. `promptAction.showToast/showDialog` 仍可使用，但有 deprecation WARN —— 暂留待官方升级路径
  7. `Base64.encodeToString / decodeSync` 已 deprecated，且新签名返回 `Promise<string>` 不是 `string`，改自定义 Base64 编码（标准 4-char / 6-bit 转换）
  8. `connection.getNetCapabilities()` 在 HarmonyOS 7 上签名变更（`NetCapabilities` 不可迭代），P1 阶段直接返回 unknown 走双地址探测
  9. `ConfigurationConstant.Configuration` 类型不导出；`onConfigurationUpdate` 形参类型用 `ESObject` 兜底
  10. `fontSizes` 必须显式声明 `s` 字段（mobile 原版的 `s` 大小与 `sm` 不同），原版没有 `s` 时也会报错"Property 's' does not exist"
  11. `TextInput.onChange((v: value) => ...)` 形参名 `value` 是 ArkTS 全局类型不能用，改 `(v: string) => ...`
  12. `Row.maxWidth(600)` 不存在，改 `constraintSize({ maxWidth: 600 })`
  13. `Image(book.coverUrl)` 接受 `string | Resource`，不需要 `getCoverImageUrl` 中转
  14. `Private constructor` 在 strict mode 下导致外部 `new ApiClient` 失败，要么改 public，要么把工厂函数挪进 class 内部 static method；本项目改 public 并在 `getApiClient()` 中加 fallback `if (!apiClientInstance) apiClientInstance = new ApiClient({ baseURL: 'http://localhost:8088/api' })`
  15. `@Entry` 组件的 `build()` 必须**单根节点**；多 modal + 主 column 组合场景把整个 Column 包进 `Stack` 即可

### ArkWeb API 差异(mobile react-native-webview → ArkWeb)
- `javaScriptEnabled` → `.javaScriptAccess(true)`
- `domStorageEnabled` → `.domStorageAccess(true)`
- `source={{html}}` → `src: 'data:text/html;charset=utf-8,' + encodeURIComponent(html)`
- `ref.injectJavaScript(js)` → `WebviewController.runJavaScript(js)`
- **`onMessage` 不存在** → 用 `.javaScriptProxy({ object: jsBridge, name: 'readerBridge', methodList: ['postMessage'], controller })`;H5 侧 `window.ReactNativeWebView.postMessage(...)` 全部替换为 `window.readerBridge.postMessage(...)`(ReaderHtml.ets 全局 replace_all,~10 处)。
- 桥接对象必须是独立 class(ReaderJsBridge)持有 screen 引用,methodList 数组里列公开方法名;被调方法必须 public。
