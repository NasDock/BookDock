## hm 听书起点按入口区分
- 需求：详情页点听书 → 恢复上次听书位置（跨章）；阅读页点听书 → 若当前章=上次听到一半的章则续听，否则从当前章开头。
- 后端事实：`GET /tts/progress?bookId=x`（不带 chapterIndex）返回该书全部章节进度数组，按 chapterIndex 升序，每条带 updatedAt；`tts-progress.service.ts` 的 `getAllForBook` 实现。单章带 chapterIndex 则只取该章。
- 数据字段坑：后端 `TtsProgressResponseDto` 返回 `provider`/`voice`，hm model 原来只读 `currentProvider`/`currentVoice`（从不返回），已在 `TtsProgressRecord` 加 `provider`/`voice` 并在恢复时 `rec.provider ?? rec.currentProvider` 兼容。
- 改动链：`AppRouter.TTSParams` 加 `source`/`currentChapter` → `ReaderScreen.handleTTS` 传 `source:'reader',currentChapter:this.currentChapter`；`BookDetailScreen.handleTTS` 传 `source:'detail'`（import 加 TTSParams）→ `MainTabNavigator.PageBuilder` 透传 `initialSource`/`initialChapter` → `TTSScreen` 加同名 @Prop。
- `TTSScreen.fetchLastTtsProgress()` 取全书进度按 `Date.parse(updatedAt)` 最新一条；`loadInitialData` 据此算 `startChapter`/`resume`；`loadChapter(ci,skipEmpty,resume=true)` 新增 resume 参数，false 时段落/偏移归零但保留音色倍速偏好。手动切章 `handleChapterChange` 仍用默认 resume=true。
- 之前 hm 与 mobile 一致固定 `loadChapter(0,true)`，本次是有意的行为分叉（mobile 未改）。需 DevEco 编译/真机验证。

## desktop 听书起点恢复逻辑（三端对齐）
- 顺带修既有坏链：`Reader.tsx` 的 `onNavigateTts` 原来 navigate `/reader/${id}/tts`，但 `App.tsx` 只注册 `/book/:id/tts`，路由根本不存在；改为 `/book/${id}/tts?ci=${currentChapter}&source=reader`。
- `BookDetail.handleTTS` 的 URL 加 `&source=detail`；原有 `getBookLastRead` 算 ci 的逻辑保留作 fallback。
- `Reader-TTS.tsx` 按 `source` 三路决策：`reader` 以 URL ci（阅读页当前章）为准，仅当全书最新 TTS 进度同章且 para/offset>0 才 resume，否则从头；`detail` 取全书 TTS 进度 `updatedAt` 最新一条跨章恢复；无 source 沿用原 `?ci > getBookLastRead > tts progress > 0`（queue-end 自动切章等调用点不受影响）。
- `loadChapter` options 加 `resume?: boolean`，false 时跳过整个 `getTtsProgress(bookId, ci)` 恢复块（含 provider/voice/loadVoices），resumeParaIdx/resumeOffset 保持 0。
- desktop 原本已有 last-read + TTS 进度 fallback，但无入口区分且 loadChapter 无条件恢复段落；本次只加分支，未动其他调用点。
- 校验：`git diff --check` 通过；desktop 的 `npx tsc --noEmit` 零错误（exit 0）。
