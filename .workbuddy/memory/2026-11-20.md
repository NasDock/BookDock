## API Token 管理与鉴权（三端设置页）— 已提交 f5d9d83 到 origin/feat/test

### 需求
用户要一套 access token（个人访问令牌）：能增删改查；除用户信息外所有接口可用 token 访问；现有 public 接口保持匿名可访问；三端设置页新增 token 管理页。

### 后端（apps/server）
- **复用现有 `ApiKey` prisma model / `api_keys` 表**（字段已齐：keyHash/lastUsedAt/expiresAt/isActive，sha256 存储），不改 schema、不加迁移。全项目此前零业务代码用这张表。
- 新增 `src/modules/api-key/`（controller/service/dto/module），注册到 app.module。
  - `GET/POST/PUT/DELETE /api/api-keys`，全部 JWT 保护，`@CurrentUser('sub')` 限定只操作自己的。
  - token 格式 `bd_` + 32 字节 hex，**明文仅创建时返回一次**，库里只存 sha256。
  - 注意 `keyHash` 在 schema 里只有 `@@index` 非 `@unique`，校验时用 `findFirst` 不能用 `findUnique`（编译踩过坑）。
- 新增全局 `ApiTokenGuard`（APP_GUARD 注册在 app.module providers）：只认 `bd_` 前缀 token，非 token/JWT 请求直接放行 → public 接口行为不变。
  - 校验后注入 `request.user = {sub, email, role, tokenType:'api-key'}`，与 JWT payload 同形，`@CurrentUser` 无需改。
  - 用户信息/账号类接口 deny-list：`/api/auth*`、`/api/admin*`、`/api/api-keys*`、`/api/vip/profile` → 403。
  - 书签/收藏/阅读进度等个人内容接口放行（token 注入的 sub 天然隔离数据）。
  - 改造 `JwtAuthGuard`/`OptionalJwtAuthGuard`：识别出 api-token 的 request.user 就直接放行，避免二次 JWT 校验。
  - token 支持三种传法：Authorization Bearer、query `?token=`、header `X-API-Key`。

## Android CI 报错修复 — 已提交 69ba974 到 origin/feat/test
- 现象：`android-actions/setup-android@v3` 执行 `sdkmanager tools` 报 `Failed to find package 'tools'` + exit 1，Android 打包挂掉。
- 根因：Google 已下架旧 `tools` 包；v3 的默认包列表仍含它。官方在 **v4** 把它移出默认列表（默认只装 platform-tools），input 与 v3 兼容、无破坏性变更。
- 改动：`.github/workflows/android-release.yml` 和 `feat-test-release.yml`（build-android job）各一处 `@v3` → `@v4`。YAML 语法校验通过。
- 已推送；push 会自动重跑 feat-test-release 的 Android 构建，可用于验证修复。
