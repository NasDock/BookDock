## hm「关于 BookDock」版本号改为动态读取

- 现象：改了 app.json5 versionName 后，设置页「关于 BookDock」仍显示 `1.0.0`——`SettingsScreen.ets:57` 把 `@State appVersion` 硬编码成 `'1.0.0'`，refreshAll 无赋值。mobile/desktop 都是动态读（mobile `require('../../package.json').version`，desktop Vite `define` 注入 `VITE_APP_VERSION`）。
- 修复：`SettingsScreen.ets` 加 `import { bundleManager } from '@kit.AbilityKit'`；appVersion 初始值改 `'-'`；refreshAll 里调 `loadAppVersion()`，用 `bundleManager.getBundleInfoForSelfSync(bundleManager.BundleFlag.GET_BUNDLE_INFO_WITH_APPLICATION).versionName` 动态取 app.json5 版本名（同步 API，放刷新流程即可），异常回退 `'-'`。
- 坑：SDK 里 `versionName`/`versionCode` 在 `BundleInfo` 自身（`ets/api/bundleManager/BundleInfo.d.ts:130/158`），**不在 `appInfo`**（ApplicationInfo 无此字段，`info.appInfo.versionName` 编译报 10505001）。
- 验证：hvigor CLI `BUILD SUCCESSFUL`（仅存量警告）。从此改 app.json5 版本号，关于页自动同步，无需再改代码。

## 切换 hm 为正式包签名（准备上架）

- 背景：`build-profile.json5` 的 `products[0].signingConfig` 之前为方便真机 debug 指向 `"debug"`；正式材料在 `signingConfigs[0] name="default"`（bd.p12 + bdRelease.p7b + bd.cer）。
- 改动：`products[0].signingConfig` 从 `"debug"` → `"default"`（一行）。
- 验证：hvigor CLI `-p buildMode=release assembleHap` `BUILD SUCCESSFUL`；产物 `entry/build/default/outputs/default/entry-default-signed.hap`（~1.5MB）。正式 profile `bdRelease.p7b` 确认含 `release`+`app_gallery`+`app-distribution-type`、无 `debug`、bundle-name `com.bookdock.app`。bd.cer 是完整 3 张证书链。
- 注意：**切回 debug 真机调试时要再把该字段改回 `"debug"`**；反之打正式包保持 `"default"`。材料在 `/Users/ctjj/Documents/资料/bd/`。
- 【上架自检失败坑】首次打的包 `module.json` 仍带 `"debug":true`/`"buildMode":"debug"` → 应用市场拒绝上架。根因：`-p buildMode=release` 配合 `--incremental --daemon` 时，增量缓存复用了之前 debug 构建生成的 `module.json`，release 参数没真正重编。解决：`hvigorw --stop-daemon` → `rm -rf entry/build .hvigor/cache` → 用 `--no-incremental`（不带 --daemon）重建。验证方式：解压 HAP `unzip -p xxx.hap module.json | python3 -c "import json,sys; print(json.load(sys.stdin)['app'].get('debug'))"` 必须为 False。正式包命令：`--mode module -p module=entry@default -p buildMode=release assembleHap --no-incremental`。
