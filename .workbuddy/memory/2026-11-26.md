## hm 冷启动后播完当前段就停
- 根因：`TTSPlayer.handleCompleted` 在 `queueIndex >= queue.length`（队列播空）时只调 `synthesizeAndEnqueueParagraph` 把下一段合成入队，**没有再调 `playQueueItem`**。冷启动后服务端首次合成慢，playParagraphs 的 fire-and-forget 预取常赶不上当前段播完，于是队列空了、播放停止。
- 附带缺陷：`paragraphChunkStart` 存的是队列段序号（从 0 起），而 `currentParagraphIndex` 是绝对段落索引；从中间段恢复时 `findParagraphIndexByQueueIndex` 返回队列序号，切段会跳回错误段落。
- 修复（`TTSPlayer.ets`）：
  - 队列播空时 `synthesizeAndEnqueueParagraph(...).then()` 等合成入队后主动 `playQueueItem(queueIndex)` 续播；合成仍失败则 setState(ERROR) 而非静默卡在"播放中"。
  - 新增 `paragraphChunkIndices` 与 `paragraphChunkStart` 一一对应存绝对段落索引；`queueHasParagraph` 改按绝对索引判断；`findParagraphIndexByQueueIndex` 返回绝对索引。
  - 新增 `enqueueTasks: Map<number, Promise<void>>` 复用 in-flight 合成，避免预取与续播并发重复合成/重复入队；stop/release 一并清理新字段。
- 验证：`-p buildMode=debug assembleHap` BUILD SUCCESSFUL（当前仍 debug 签名）。

## hm 退后台停止播放（AVSession + 长时任务）
- 根因（HarmonyOS 官方规范）：流类型为 STREAM_USAGE_MUSIC/MOVIE/**AUDIOBOOK**/GAME 的媒体播放，**必须接入 AVSession 并申请 AUDIO_PLAYBACK 长时任务**，否则应用退后台会被系统静音冻结/直接停止播放。项目此前没有任何相关配置。

  - `module.json5`：新增 `ohos.permission.KEEP_BACKGROUND_RUNNING`（when: always）+ `string.json` 原因文案。
