## 排查 iOS 真机"启动不了"（实为 metro 端口冲突）

- 现象：用户说 iOS 真机连了但启动不了。实测 `expo run:ios --device <udid>` 其实 **Build Succeeded + 安装成功**（app 进程已在真机跑），编译/签名没问题。
- 根因：运行时 app 拉 JS bundle 连错 metro。`AppDelegate.mm` 用 `RCTBundleURLProvider` DEBUG 默认拉 `localhost:8081`；但 8081 被**另一个项目 AudioDock（声仓）的 stale metro**（pid 92882）占着，服务的是 AudioDock bundle（22MB、满是 react-native-track-player，且自身报 shaka-player 找不到）；BookDock 自己的 metro 被挤到 8082（pid 17937，9.2MB、含 BookDock/LoginScreen 才是对的）。`expo run:ios` 日志 `Waiting on http://localhost:8081` 是因看到 8081"有响应"就复用，没起自己的 metro → app 加载错 bundle → 白屏起不来。
- 排查手法：①`xcrun xctrace list devices`（注意 Offline 列表）/ `xcrun devicectl list devices`（available paired 才是真可用）；②`lsof -nP -iTCP:8081 -sTCP:LISTEN -t` 找端口占用者，`lsof -p <pid> | grep cwd` 看归属项目；③用正确路径 `curl "http://localhost:<port>/.expo/.virtual-metro-entry.bundle?platform=ios&dev=true"` 取 bundle，`grep -oE 'BookDock|LoginScreen|react-native-track-player'` 判断是哪个项目（注意 SDK52 入口是 `.expo/.virtual-metro-entry`，不是老 `node_modules/expo/AppEntry.bundle`，后者会误报 500）。
- 修复：①`kill` 掉 8081(AudioDock)/8082(BookDock stale) 两个 metro；②在 `apps/mobile` 用**托管后台任务**（Bash run_in_background，`exec npx expo start --port 8081`）重启 metro——普通 `cmd &` 会随非交互 shell 退出被回收，必须用后台任务方式常驻；③验证 8081 bundle 含 BookDock 代码；④`xcrun devicectl device process terminate --device <did> --pid <pid>` 停旧 app，`xcrun devicectl device process launch --device <did> com.bookdock.app` 重启（bundle id 是位置参数，不是 `--bundle-id`）；⑤metro 日志出现 `iOS Bundled (1200 modules)` 即 app 加载成功。
- 关键事实：真机上 `localhost:8081` 指**设备自身**，但 DEBUG dev build 由 RCTBundleURLProvider 经隧道映射到 Mac 的 8081，所以 Mac 端 8081 必须是 BookDock 的 metro；多个 Expo 项目同时开会抢 8081，后开的被挤到 8082/8083，导致先装的 dev build 连错。
- 设备信息：iPhone 13 / iOS 26.6.1，UDID `00008110-0012113C3A30401E`，device id `D1E8D548-B641-5C44-A899-7860B6BC4FA6`。
- 【续·二次卡启动页】用户重跑 `expo run:ios` 后又卡启动页：这次 8081 已是 BookDock metro，但 CLI `Complete 100%` 后**立即退出**（没打 `Logs for your project will appear below`），app 拉不到 bundle。根因：`expo run:ios` 正常完成会打印 `Logs for your project will appear below. Press Ctrl+C to exit.` 并保持前台/隧道；若过早退出（如非交互环境、CI、管道 tail 截断或复用已有 metro），隧道断开，真机 app 的 `localhost:8081` 就落空。修复：用**托管后台任务**完整跑 `exec npx expo run:ios --device <udid>`（不要 tail 管道、不设 CI），等日志出现 `Logs for your project will appear below` 再确认 `iOS Bundled (N modules)`。本轮成功标志：日志 `iOS Bundled 616ms apps/mobile/index.js (1120 modules)`。
- 关键纠偏：单纯 `expo start --port 8081` + `devicectl process launch` 在本机**不可靠**——devicectl launch 起的 app 不会自动建 USB 隧道，metro 反而收不到请求；必须由 `expo run:ios` 进程自身保持运行来维系隧道。所以真机调试的稳妥姿势是让 `expo run:ios` 常驻，热更新靠它自带的 metro，别手动 kill CLI。

## 修复 iOS 模拟器打包失败（支付宝 SDK 架构）

- 现象：`npx expo run:ios`（不带 --device）打模拟器包报一堆错，真机包正常。
- 真正报错（其余 UTDID `unable to open object file` 都是干扰 warning）：`ld: building for 'iOS-simulator', but linking in object file (.../AlipaySDK.framework/AlipaySDK) built for 'iOS'` → `clang++: linker command failed`。
- 根因：`@uiw/react-native-alipay@5.0.2` 自带 `AlipaySDK.framework` 是老式 fat 包（armv7/x86_64/arm64），三个 slice 全是 `LC_VERSION_MIN_IPHONEOS`（真机），**无 arm64-simulator slice**；Apple Silicon 模拟器默认按 arm64-simulator 编，选中真机 arm64 slice → 平台不匹配链接失败。
- 修复：在 `apps/mobile/ios/BookDock.xcodeproj/project.pbxproj` 的 **project 级 Debug/Release buildSettings** 各加一行 `"EXCLUDED_ARCHS[sdk=iphonesimulator*]" = arm64;`（键含方括号必须加引号，否则 pbxproj 解析报 `SyntaxError: Expected ... but "[" found`；用 `plutil -lint` 校验）。只影响模拟器（走 x86_64 + Rosetta），真机 iphoneos 不受影响。备份 `/tmp/BookDock-project.pbxproj.bak-20261119-231549`。
- 改配置后必须清增量缓存：`rm -rf <DerivedData>/Build/Products/Debug-iphonesimulator <DerivedData>/Build/Intermediates.noindex/BookDock.build/Debug-iphonesimulator`，否则复用旧 arm64 产物。DerivedData=`~/Library/Developer/Xcode/DerivedData/BookDock-ehztsqqhsjlhhmeddpsxrisxtqvl`。
- 结果：`Build Succeeded`，产物 `BookDock.app/BookDock` 为 x86_64。
- 后续坑：Expo 启动模拟器环节用 `osascript ... count processes whose name is "Simulator"`（System Events 自动化权限）在本环境被拒，`expo run:ios` 最后一步失败但**编译已成功**。绕过：手动 `xcrun simctl install <sim-udid> <BookDock.app>` + `xcrun simctl launch <sim-udid> com.bookdock.app`（iPhone 17 = AE2A5E23-B672-4ADC-950D-9AE07309B05B，已 Booted）。模拟器 DEBUG 包同样连 8081，需另起 `expo start --port 8081` 常驻；terminate+launch 触发重载，metro 日志 `iOS Bundled (1254 modules)` + `LOG [PlaybackService] Registered` 即成功。

## hm 平板横屏登录表单溢出屏幕右边界

- 现象：用户反馈 pad 模式下登录表单「超过边界」。模拟器 `127.0.0.1:5555`（2560×1600 横屏）截图证实：右侧输入框、密码框眼睛图标、登录按钮右半截被裁出屏幕，左侧二维码位置正常。

- 修复（仅 `apps/hm/entry/src/main/ets/screens/LoginScreen.ets`）：
  - 横屏：对齐 mobile `contentLandscape(row+gap40)` / `formCard(flex:1, minWidth:0)` 语义 —— `FormPanel()` 外包一层 `Column()`，用 `.layoutWeight(1)` 吃剩余空间 + `.constraintSize({maxWidth:360})` 封顶；Row 整体 `.constraintSize({maxWidth:680})` + `.alignItems(VerticalAlign.Center)`。**关键：Row 内不能用 `width('100%')`，必须用 layoutWeight。**
