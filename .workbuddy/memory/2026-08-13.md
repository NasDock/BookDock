## 修复 mobile2 LoginScreen 动态 import 导致的模块解析错误

- **症状**：mobile2 数据源登录页面点击登录按钮报错 `LoadBundleFromServerError: Could not load bundle`，`Caused by: Unable to resolve module ./packages/api-client/src/index from /Users/ctjj/Documents/projects/BookDock/apps/mobile2/.`
- **根因**：`LoginScreen.tsx` 里有两处 `await import('@bookdock/api-client')` 动态 import。Metro 编译时正确解析 `@bookdock/api-client` → `packages/api-client/src/index.ts`，但生成 async bundle 路径时 `path.relative(serverRoot, absolutePath)` 得到 `../../packages/api-client/src/index.ts`。拼到 URL 后 `..` 被 HTTP 层解析掉，实际请求变成 `/packages/api-client/src/index.bundle`。Metro 服务器把它当作相对于 `projectRoot`（`apps/mobile2`）的路径，`apps/mobile2/packages/api-client/src/index.ts` 不存在，报错。
- **修复**：把两处 `await import('@bookdock/api-client')` 改成静态 import。`LoginScreen.tsx` 已经有 `import { initApiClient } from '@bookdock/api-client'`，只需把 `getApiClient` 也加进去，然后直接使用。
  ```diff
  -import { initApiClient } from '@bookdock/api-client';
  +import { initApiClient, getApiClient } from '@bookdock/api-client';
  ```
  ```diff
  -const apiClient = (await import('@bookdock/api-client')).getApiClient();
  +const apiClient = getApiClient();
  ```
  ```diff
  -const { getApiClient } = await import('@bookdock/api-client');
  -const apiClient = getApiClient();
  +const apiClient = getApiClient();
  ```
- **验证**：Metro bundle 成功打包（6MB，无错误），TypeScript 编译通过，bundle 中不再有任何 `api-client/*.bundle` 的 async bundle 路径。
- **推广教训**：在 pnpm monorepo 的 RN 子项目中，**避免对 workspace 包使用 `await import()`**。Metro 为 workspace 包生成的 async bundle 路径包含 `../..`，URL 解析后路径错误。如果必须用动态 import，需要设置 `server.unstable_serverRoot` 为 workspace 根，但这会影响入口文件解析，需要额外处理。

## 修复 BookDock mobile 横屏左侧白/黑横条

- 现象：mobile 端**Android**横屏时，**距离摄像头那侧**（竖屏时系统状态栏区域）出现一条**白条或深色不一致的横条**（截图1 推荐页深色主题 → 左侧白条；截图2 设置页深色主题 → 左侧略深一条），且不跟随主题色变化。AudioDock mobile 横屏没有这个问题。
- **重要：用户澄清是 Android 问题（不是 iOS）**，第一轮我误判成了 iOS react-navigation 6 的 safe area 问题，修复方向完全错。撤掉 iOS 那套思路后重新诊断。
- 真正的根因（**Android native 层控制问题**）：
  - `apps/mobile/android/app/src/main/res/values/styles.xml` 第 7 行硬编码 `<item name="android:statusBarColor">#ffffff</item>`（**白色**）—— 这个颜色是 **Android Window-level 属性**，JS 层完全控制不到。
  - `apps/mobile/app.json` 的 `android` 块没设 `edgeToEdgeEnabled`，所以 status bar 由系统保留半透明+window.statusBarColor=白色的默认行为。
  - AudioDock 在 `app.json` 的 android 块里有 `"edgeToEdgeEnabled": true`，启用后 React 内容延伸到 status bar 下方，status bar 透明 → React 内容 backgroundColor 显示 → **白色硬编码被覆盖**。这才是 AudioDock 没有这个问题的根本原因。
  - AudioDock 的 `styles.xml` 第 6 行其实也硬编码了 `<item name="android:statusBarColor">#ffffff</item>`，但因为 edgeToEdgeEnabled=true 让它失效了。
- 修复（**两层**）：
  1. **主修复**：`apps/mobile/app.json` 的 `android` 块加 `"edgeToEdgeEnabled": true`，对齐 AudioDock。
  2. **辅助兜底**：`apps/mobile/src/App.tsx` 在 `SafeAreaProvider` 里包一个 `<View style={{ flex: 1, backgroundColor: theme.colors.background }}>` 包住 `RootNavigator`。
     - 这一层在 Android 启用 edgeToEdge 后是**冗余**的（edgeToEdge 已经把背景延伸到 status bar 下方），但保留无害，作为 iOS 端的兜底（iOS 横屏侧安全区行为差异）。
     - `getTheme(actualTheme === 'dark')` 每次 render 重算，`actualTheme` 切换时 backgroundColor 自动响应 → 横条跟着主题色变。
- 没改的东西：
  - **没动 `styles.xml` 的 `android:statusBarColor="#ffffff"`**：edgeToEdgeEnabled=true 后这个值被忽略，留着不动避免触发 Expo prebuild 重生成。
  - **没动 navigationBar.ts**：setNavigationBarAuto 在 edgeToEdge 模式下被 system 接管，但 BookDock 还在调用，没坏处。
  - **没改各 screen 的 SafeAreaView edges**：那是"重复顶部 inset"问题（今天前面那两条），不是横条问题。
- 验证：需要在 Android 真机或模拟器横屏看效果。建议用户冷启动一次 app（因为 app.json 改动需要 Expo prebuild + native rebuild 才生效）。

### monorepo semver 冲突坑（新发现，已修）

启动 mobile2 报：
```

  .../react-native-reanimated@4.1.7_*/node_modules/react-native-reanimated/scripts/validate-worklets-version.js
```

**根因**：
- reanimated@4.1.7 的 build-time 脚本 `require('semver/functions/prerelease')`
- 这是 semver **v7+ 才有的 subpath export**（v6 没有）
- monorepo 根 `node_modules/semver` 被 pnpm hoist 成了 v6.3.1（pnpm 默认挑最少项目的版本）
- reanimated 自己的 sibling semver 是 v7.7.4 ✅，但 babel plugin 在 mobile2 目录加载时 require 走到了根的 v6
- mobile2 自己没声明 semver → 没强制 v7

**教训**：在 monorepo 装任何**有 build-time 脚本**的 native 包（reanimated / native modules）
时，先检查这个 native 包 peer dep 的 semver 是不是 ≥ v7，是的话子项目就要显式声明 semver^7，
否则根 hoist 会被旧版本覆盖。**不要**用 `pnpm.overrides` 全局强升，会影响 desktop/server 等其他子项目。

## mobile2 metro 解析 @bookdock/* workspace 包失败（2026-08-13）

**症状**：`LoadBundleFromServerError: Could not load bundle, Caused by: Unable to resolve module ./packages/api-client/src/index`
**根因**：`apps/mobile2/metro.config.js` 的 `resolver.nodeModulesPaths` 漏了 `BookDock/packages/` 路径。
- pnpm symlink 路径：`apps/mobile2/node_modules/@bookdock/api-client -> ../../../../packages/api-client/`
- 物理位置：`BookDock/packages/api-client/src/index.ts`
- metro 解析时跟 symlink 到 packages/，但 nodeModulesPaths 不含 packages/ → disableHierarchicalLookup=true 阻止向上递归 → fallback 失败
- **之前能进 LoginScreen** 是因为 LoginScreen 是 25 行占位不 import api-client，不触发这个解析；刚写的完整 635 行版本第一次引用 `initApiClient` / `apiClient` 才暴露

**修复**（已做 2026-08-13）：`metro.config.js` 加 `path.resolve(workspaceRoot, 'packages')` 到 `nodeModulesPaths`，**同步**加到 `watchFolders` 让 packages/* 变更触发 reload

**经验教训**：
- pnpm monorepo + @react-native/metro-config + 纯 RN（无 expo）时，**nodeModulesPaths 必须**含 workspace 的 `packages/` 目录
- mobile 原版用 expo 默认配，expo metro resolver 自动处理；mobile2 用纯 RN 不会自动处理
- **容易在没写引用某个包时掩盖问题**，直到第一次引用才暴露——给移植工作埋雷
