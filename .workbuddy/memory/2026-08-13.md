## 修复会员权益页 header 下面一大块空白
- 文件：`apps/mobile/src/screens/MemberBenefitsScreen.tsx` line 482-486
- 现象：mobile 端进入「会员权益」页（MemberBenefitsScreen），header 下面紧贴着表头，对比表卡片前面有一大段空白（约 68px：SafeAreaView top inset ≈ 44px + scrollContent paddingTop 24px）。
- 根因：React Navigation native-stack header 已经处理了顶部 status bar / notch，但 `SafeAreaView`（默认 edges = top/right/bottom/left）又拿设备级 insets 算了一次 top padding，导致重复。

  证据：
  1. RootNavigator.tsx:158-161 给 `MemberBenefits` 配了 `headerShown: true`（默认）+ title，header 自带 status bar 高度。
  2. App.tsx:116 的 `SafeAreaProvider` 没传 `initialMetrics`，默认从 native module 拿设备级 insets（status bar 高度），**不会**因为 native-stack 的 Screen frame 而变成 0。
  3. 对比 `SearchScreen.tsx:165` `edges={['top', 'left', 'right']}` —— SearchScreen 是 `headerShown: false`（RootNavigator.tsx:138），所以它**需要** top edge；MemberBenefits 是 `headerShown: true`，**不需要**。

  为什么 MemberDetailScreen 同样默认 edges 但没暴露：它的第一个元素是紫色大卡片（memberCard），视觉占位强，重复的 top inset 不明显；MemberBenefits 的第一个元素是白底浅边框对比表（tableCard），视觉上"轻"，重复 top inset 暴露成大段空白。
- 修复（最小侵入式，1 行 + 注释）：
  ```tsx
  <SafeAreaView edges={['left', 'right']} style={[styles.container, { backgroundColor: theme.colors.background }]}>
  ```
  - top edge 去掉：React Navigation header 已经处理 status bar
  - bottom edge 去掉：`scrollContent.paddingBottom = 40` 已经覆盖 home indicator
  - 水平方向保留：Android landscape 时的左侧 notch / 摄像头凹槽仍需处理
- 验证：
  - `cd apps/mobile && npx tsc --noEmit -p tsconfig.json` → MemberBenefitsScreen.tsx 上 0 错误；总错误数跟 baseline 一致（全是历史遗留：RootNavigator/LibraryScreen/LoginScreen/MemberLoginScreen/ScanLoginScreen/StatsScreen/TTSScreen/playbackService 的 `["Search"]` 不匹配、`ScanLoginSession` 缺字段等，与本次无关）。
- 待办（用户可选）：
  1. SettingsScreen / MemberDetailScreen / AdminUsersScreen 同样用 `SafeAreaView` 默认 edges + React Navigation header 的 4 个页面也都有这个重复 top inset 问题，但视觉上没暴露。要不要顺手统一改成 `edges={['left', 'right']}` 取决于设计偏好 —— 我倾向于先只动这一个，等用户后续反馈再统一。
  2. AudioDock 那边的 `member-benefits.tsx` 用的是 `<View paddingTop={insets.top}>` + 自绘 header（不是 React Navigation header），所以**它的 paddingTop: insets.top 是必要的**。BookDock 这边不能照搬这个 pattern，除非把 React Navigation header 拿掉换成自绘 header（不推荐，会丢 navigation 默认手势返回）。
